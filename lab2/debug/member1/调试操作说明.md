# QEMU 地址翻译调试操作说明

## 环境与目标

本目录的主机断点脚本针对 QEMU 4.1.1 源码。发行版 QEMU 可用于内核运行验证，但不能把其他版本的调用路径和变量名当成 4.1.1 的实测结果。主机 GDB 调试 QEMU 的 x86_64 进程，RISC-V GDB 或 gdb-multiarch 调试内核。

准备带调试符号的 QEMU 4.1.1，在其源码目录执行：

```sh
./configure --target-list=riscv64-softmmu --enable-debug
make -j2
```

使用与旧版本兼容的 Linux 构建环境并先安装其构建依赖。如果原目录曾有其他配置，先运行 `make distclean`。不需要 `make install`，直接使用源码目录下的可执行文件。较新发行版可能需要额外处理旧 QEMU 的 Python 与编译器兼容问题。

## 三个终端的操作顺序

终端一进入 lab2 目录，先编译，再启动指定版本：

```sh
make
make debug QEMU=/绝对路径/qemu-4.1.1/riscv64-softmmu/qemu-system-riscv64
```

终端二查找这个 QEMU 的 PID，确认命令行确实对应本次实验。先 `pgrep -af qemu-system-riscv64`，再运行主机 GDB：

```sh
gdb /绝对路径/qemu-4.1.1/riscv64-softmmu/qemu-system-riscv64
```

```gdb
attach 实际PID
source /绝对路径/lab2_member1/debug/qemu4_mmu.gdb
continue
```

如果系统拒绝同用户附加，使用 `sudo gdb` 启动这一个调试会话即可。不要为此全局关闭 ptrace 限制。

终端三在 lab2 目录执行：

```sh
gdb-multiarch -x ../debug/kernel.gdb
```

QEMU 进程被主机 GDB 停住时，内核 GDB 可能等待回复；切回主机 GDB 继续，才能恢复内核 GDB 的连接和执行。断点停下后不要同时在两个窗口反复发送命令。

## 捕获一次翻译

主机断点第一次停下后执行 `bt`。若调用方是 `riscv_cpu_get_phys_page_debug`，这是调试器读内存触发的查询，应继续寻找来自 `riscv_cpu_tlb_fill` 的执行路径。脚本默认筛选内核起始 4 KiB；如没有命中，按实际内核地址调整条件。

```gdb
info args
p/x addr
p access_type
p mmu_idx
p/x env->satp
list
next
```

逐行执行到 Sv39 分支，记录 `levels=3`、`ptidxbits=9`、`ptesize=8`。继续到读取 PTE 后，依次记录：

```gdb
p/x base
p i
p ptshift
p/x idx
p/x pte_addr
p/x pte
p/x ppn
```

变量必须执行到赋值后再查看；若变量被优化，改用调试构建、在赋值语句后设断点或查看反汇编。用 `next` 越过物理读函数，避免进入大量无关代码。记录叶项判定、权限检查和物理页基址赋值。`get_physical_address()` 的输出在此版本中是物理页基址；完整物理地址还要加原地址低 12 位。

本实验 entry.S 的根页表第 511 项为 `0x200000cf`，是 1 GiB 叶映射。循环支持最多三层，但本映射在第一轮就完成。对 `0xffffffffc0200000`，预测完整 PA 为 `0x80200000`；这是静态计算，须用自己的断点日志核对。

## 观察 TLB

先把当前翻译观察完整，再单独设 `break riscv_cpu_tlb_fill`、`break tlb_set_page`；适当增加 `address` 的条件，避免对所有访存暂停。C 慢路径的 TLB 检查在 `accel/tcg/cputlb.c` 中，查找 `load_helper`、`tlb_hit` 和 `victim_tlb_hit`。内联函数不一定能直接按函数名断住，可按源码行设断点。

TCG 还会生成快速查表的主机代码，因此并非每次客体访存都进入 C helper。不要把“某个 C 断点没命中”直接解释为没有查 TLB。取指也可能复用已翻译的 Translation Block。

比较 Bare 与 Sv39 时应记录 `satp.MODE`、有效权限模式和调用栈。Bare 或有效 M 模式可直接映射，但 QEMU 仍可能使用软件 TLB 缓存到宿主地址的访问关系。QEMU 软件 TLB 和真实硬件 TLB 的职责、结构与实现位置不同。

## 本次实测证据

| 项目 | 实测记录 |
|---|---|
| QEMU 版本与构建选项 | os2026 现有 4.1.1 源码构建，含 debug_info，`-O2 -g` |
| 访问指令及读写取指类型 | `kern_init: auipc a0,0x6`，取指访存 |
| 访问 VA 与 satp | `0xffffffffc02000d8`，`0x8000000000080205` |
| 调用栈及命中断点 | `get_page_addr_code → tlb_fill → riscv_cpu_tlb_fill → get_physical_address` |
| 根页表 PA 与 PTE 地址 | `0x80205000`，`0x80205ff8` |
| PTE 值、权限、叶项级别 | `0x200000cf`，VRWXAD，根级 1 GiB 叶项 |
| 物理页基址与完整 PA | `0x80200000`，`0x802000d8` |
| TLB miss、填充与后续命中证据 | `addr_code` 从全 1 变为 `0xffffffffc0200000`，完整调用栈见日志 |
