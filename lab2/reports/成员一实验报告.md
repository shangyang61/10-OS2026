## 三 物理内存初始化的规格

接口为 `static void page_init(void)`，无输入参数、无返回值，由 `pmm_init()` 调用。

输入来自 `get_memory_base()`、`get_memory_size()`、链接符号 `end` 以及框架提供的地址转换和页面宏。输出是全局变量 `va_pa_offset`、`npage`、`pages` 和当前管理器中的初始空闲页区间。

实现满足以下条件：

1. 设备树内存起址和大小不能为零，起址与大小求和不能溢出。
2. 物理内存必须覆盖本框架固定的 DRAM 基址及内核所在区域。
3. 可管理上界取设备树末端与 `PHYSICAL_MEMORY_END` 的较小值，并向下按页对齐。
4. `npage` 是可管理末端的绝对物理页号，描述符数量为 `npage - nbase`。
5. 描述符数组放在内核结束地址之后，起始地址向上按页对齐；写入前验证数组能完整放入可管理内存。
6. 先将全部描述符置为保留状态，再由管理器释放合法空闲区，避免内核、OpenSBI 和描述符数组对应的物理页被分配。
7. 空闲起点为描述符数组末端向上按页对齐的地址，只有非空的完整页面区间才能传给 `init_memmap()`。

该实现遵循实验框架的单段连续 DRAM 和固定 `nbase` 约定，并未扩展为支持任意多段 RAM 的通用内存管理器。

## 四 核心实现说明

### 地址与页号

`va_pa_offset` 设置为 `PHYSICAL_MEMORY_OFFSET` 后，`PADDR()` 才能将内核虚拟地址转为物理地址。不能把 `end` 的高位虚拟地址直接与设备树返回的物理地址比较。

本次内存为 `[0x80000000, 0x88000000)`，所以 `nbase=0x80000`、`npage=0x88000`，二者之差为 32768 个页面。若错误地将 `npage` 设置为 32768，`pa2page()` 的地址检查和描述符索引就不再符合框架约定。

### 描述符与保留空间

`pages` 指向描述符数组的虚拟地址。对数组中的每个描述符清理状态、设置保留标志、将引用计数和 `property` 置零，并初始化链表节点。随后才向当前物理内存管理器登记空闲页。

本次验证内核的实际布局如下，地址会随代码大小变化：

| 项目 | 数值 |
|---|---|
| 内核结束虚拟地址 | `0xffffffffc0206078` |
| 描述符数组虚拟地址 | `0xffffffffc0207000` |
| 描述符数组物理地址 | `0x80207000` |
| `sizeof(struct Page)` | 40 字节 |
| 描述符数组大小 | `32768 × 40 = 0x140000` 字节 |
| 空闲区起始物理地址 | `0x80347000` |
| 可管理末端物理地址 | `0x88000000` |

由上述实测值计算，初始空闲区为 `[0x80347000, 0x88000000)`，共 31929 页。内核之前、内核本体和描述符占用的页面均位于这段区间之外。

### 异常与边界

缺失或溢出的设备树信息直接调用 `panic()`。内核或描述符超出可管理范围也终止初始化。描述符能放下但已经没有完整空闲页时，不调用 `init_memmap()`，防止传入零页触发管理器断言。最后一种情况通过隔离测试验证；常规内核自检本身需要有可分配页面。

脚本保存原始主机调试日志和内核调试日志。源码行号对应虚拟机内这份 QEMU 4.1.1 源码，其他源码版本需重新定位。内核 GDB 的内存读取也可能调用地址翻译函数，因此以调用栈中出现 `riscv_cpu_tlb_fill` 作为识别执行路径的重要依据。

### 一次实际取指翻译

本次观察 `kern_init` 首条指令，内核反汇编显示：

```text
0xffffffffc02000d8 <kern_init>: auipc a0,0x6
```

主机 GDB 在对应翻译的 PTE 检查处暂停，再执行多次 `next`，实际经过有效位、叶项、权限、大页对齐和 A/D 位相关检查，随后执行物理页基址计算。记录值如下：

| 观察项 | 实测值 |
|---|---|
| 访问虚拟地址 | `0xffffffffc02000d8` |
| 访问类型 | `MMU_INST_FETCH` |
| 有效模式 | S 模式，`mmu_idx=1` |
| `satp` | `0x8000000000080205` |
| 根页表物理地址 | `0x80205000` |
| 本轮 `i`、`levels`、`ptshift` | 0、3、18 |
| 根级索引 | 511 |
| PTE 物理地址 | `0x80205000 + 511×8 = 0x80205ff8` |
| PTE | `0x200000cf` |
| PTE 中的物理页号 | `0x80000` |
| 翻译函数输出的物理页基址 | `0x80200000` |
| 完整物理地址 | `0x80200000 + 0xd8 = 0x802000d8` |

启动页表只有根级第 511 项有效，该项本身是 1 GiB 大页叶项。因此 `levels=3` 表示 Sv39 最多支持三层，本次查询在循环第一轮完成，不会再读取下一级页表。本次转换保留了虚拟地址相对于这段 1 GiB 映射的低 30 位偏移。

这里展示的是取指访存。日志还捕获到 `store_helper → tlb_fill → riscv_cpu_tlb_fill → get_physical_address` 的数据写入路径，例如对虚拟地址 `0xffffffffc0204ff8` 的栈写入，页基址为 `0x80204000`，完整地址为 `0x80204ff8`。

### 实际调用路径与关键分支

本次取指缺失路径为：

```text
get_page_addr_code
  → tlb_fill
  → riscv_cpu_tlb_fill
  → get_physical_address
  → tlb_set_page
  → tlb_set_page_with_attrs
```

关键分支包括：Bare 或有效 M 模式可直接映射；Sv39 从根页表开始；`V=0` 返回失败；`R/W/X` 全零则继续下一级；叶项需满足权限和大页对齐；成功后登记翻译缓存。完整现场见 `../logs/os2026_host_gdb.log`。

### TLB 未命中与命中

在 `accel/tcg/cputlb.c` 的 `get_page_addr_code()` 中，首次观察该地址时 `entry->addr_code=0xffffffffffffffff`，与目标虚拟页不匹配；随后触发翻译，并安装 `vaddr=0xffffffffc0200000` 到 `paddr=0x80200000` 的缓存项。

再次到达同一查表位置时，`entry->addr_code=0xffffffffc0200000`，与该地址所在页一致，符合命中条件。这证明了取指软件 TLB 的查找、填充和命中。数据读的 C 慢路径也实际停在 `load_helper()`，但该优化构建中的局部 `tlb_addr` 显示为 `<optimized out>`，因此没有把该变量作为数据读命中的实测证据。

### Bare 模式与硬件 TLB 的区别

启动阶段访问 `0x80200000` 时，日志显示 `satp=0`、`mmu_idx=1`，并观察到 `tlb_set_page_with_attrs` 登记 `vaddr=paddr=0x80200000`。这说明关闭客体分页后，QEMU 仍会使用自己的软件 TLB。

真实 CPU 的 TLB 由硬件实现，缓存地址翻译及权限信息；QEMU 的软件 TLB 是模拟器数据结构，还参与将客体访问快速转到宿主内存。它服务于模拟执行，并非真实硬件 TLB 的逐项复刻。TCG 会生成快速访问代码，所以不能要求每条访存都进入同一个 C helper；取指还可能复用已翻译的执行块。

## 八 Challenge 如何获取硬件可用物理内存范围

操作系统应优先取得固件或引导程序提供的内存布局，再扣除保留空间，而不是从零开始盲目尝试读写所有物理地址。

在本实验的 RISC-V 平台中，引导阶段传入 DTB，设备树 `/memory` 节点的 `reg` 属性描述物理地址与长度。内核读取这些信息得到 RAM 区间，再排除内核、固件和其他保留区域。设备树可以表达多段 RAM，通用内核还应处理保留内存描述。依据见 [Devicetree memory 节点规范](https://devicetree-specification.readthedocs.io/en/stable/devicenodes.html#memory-node)。

在 UEFI 平台上，OS Loader 可调用 `GetMemoryMap()` 获取各内存区间及类型，再将信息传给内核。传统 x86 BIOS 平台可通过 E820 接口获取系统地址映射；这不是本次 RISC-V 实验使用的接口。依据见 [ACPI 系统地址映射接口](https://uefi.org/specs/ACPI/6.5/15_System_Address_Map_Interfaces.html)。

有的嵌入式平台由启动固件根据内存控制器配置得到 RAM 布局，再以平台约定传给内核。若既没有固件描述，也没有受支持的平台接口，就无法仅靠一个通用安全读写算法可靠判定全部可用 RAM：某些物理地址对应 MMIO、保留空间或地址空洞，访问可能产生异常或设备副作用，写入还可能破坏已有数据。

取得内存范围之后仍需校验溢出、重叠、类型和页对齐，并排除内核、描述符、固件、保留数据等占用空间。物理地址存在、属于 RAM、当前可以分配，是三个不同条件。

## 十 与操作系统原理的对应关系

| 实验知识点 | OS 原理中的对应概念 | 关系与差异 |
|---|---|---|
| DTB 内存范围 | 物理地址空间与资源发现 | 固件描述 RAM；得到范围后仍要区分占用和空闲 |
| Page 数组 | 物理页帧管理 | 每个描述符代表一个 4 KiB 页帧，描述符自身也占内存 |
| reserved 标记 | 内存保留与资源保护 | 防止分配器使用固件、内核和元数据占用的页 |
| 向上向下对齐 | 分页粒度 | 分配器只登记完整物理页，避免页边界覆盖占用空间 |
| Sv39 页表 | 虚拟地址转换 | 本次根级叶项采用大页；物理页管理仍以 4 KiB 为单位 |
| 固定地址偏移 | 内核直接映射 | 本实验内核区可用减偏移转换；任意进程地址不能都这样处理 |
| QEMU 软件 TLB | 地址翻译缓存 | 可观察命中与缺失，但实现还服务于宿主内存访问 |

本部分没有实现独立进程地址空间、缺页异常处理、按需分页、页面置换、交换区、写时复制和多核 TLB 一致性。这些是 OS 内存管理的重要内容，但不能由本次 `page_init()` 和启动页表的成功推出它们已经具备。
