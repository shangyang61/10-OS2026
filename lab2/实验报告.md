## 一 实验目的与整体逻辑

实验要解决物理内存发现、按页分配和地址翻译三个相互配合的问题。系统首先从固件传入的设备树中得知 RAM 所在范围，再排除 OpenSBI、内核镜像和页描述符数组占据的区域，将剩余完整页面交给物理页分配器。First-Fit 与 Best-Fit 决定连续页块的选择方式；SLUB 在页层之上按对象分配，使小对象能够共享一页。

地址翻译则由启动页表、satp 与 TLB 完成。分配器决定哪些页可以交给调用者，页表决定虚拟地址访问哪个物理地址。分配一页不会自动建立任意虚拟地址的新映射。本实验内核预先具有直接映射，因此可以用固定偏移得到所分配物理页的内核数据地址。

当前调用顺序为：

```text
OpenSBI 交给 kern_entry
  → entry.S 设置启动根页表、satp、栈并进入高地址 kern_init
  → 清 BSS，dtb_init 读取内存信息，初始化控制台并打印符号
  → pmm_init
      → init_pmm_manager 选择并初始化 Best-Fit
      → page_init 建立保留描述符和初始空闲区
      → init_memmap 登记可用整页
      → best_fit_check 执行框架原始分配测试
  → member2_page_check 执行补充页分配检查
  → slub_init 和 slub_check
  → while (1)
```

所以 page_init 执行时已经处于分页模式。它建立的是物理页管理状态，启动页表在此前由汇编创建。

## 三 物理内存初始化与地址关系

### 3.1 四种地址量不能混用

`end` 是链接符号的内核虚拟地址；设备树返回物理基址与长度。使用 PADDR(end) 后才可以比较它们。Page 指针指向管理记录，不是对应物理页的数据空间。

```c
page2ppn(p) = p - pages + nbase;
page2pa(p)  = page2ppn(p) << PGSHIFT;
pa2page(pa) = &pages[PPN(pa) - nbase];
```

默认内存区间为 `[0x80000000,0x88000000)`，nbase=0x80000、npage=0x88000。npage 是可管理物理页号的排他上界，描述符个数为 npage-nbase=32768；它不是最终可分配页数。

### 3.2 page_init 规格与实现

接口为 `static void page_init(void)`。输入来自设备树、链接符号和框架常数，输出为 va_pa_offset、npage、pages 及当前分配器的初始空闲区。实现先验证设备树范围与溢出，取受限管理末端并向下对齐；将描述符数组放在内核末端向上对齐之后，确认数组能完整放入 RAM；先把所有描述符置为 Reserved，再把数组末端之后的完整空闲页交给 init_memmap。

起点向上对齐、终点向下对齐，是为了只交付完整页面。描述符数组本身也占物理内存，必须保留，否则调用者写入新分配的数据会覆盖页管理状态。

成员一的详细 spec、实现 prompt 和边界设计保存在其原报告。本轮再次对整合后的实际 C 函数体执行十项边界测试，覆盖正常范围、未对齐尾部、管理上界截断、缺失基址、缺失长度、求和溢出、不支持的 DRAM 起址、内核超界、描述符放不下和没有完整空闲页，结果为 10/10。该边界测试是宿主模拟内存中的实际 C 函数检查，与真实 RISC-V 启动分别记录。

## 四 First-Fit 分析与修复

### 4.1 初始化

default_init 仅初始化 free_list 哨兵和 nr_free=0。default_init_memmap 接收 page_init 确认可用的一段描述符，清保留与旧状态，引用计数置零，在块头记录 property=n 并设置 Property，随后按地址顺序插入链表。一个连续空闲块只占一个链表节点。

### 4.2 分配与分割

default_alloc_pages(n) 从低地址块开始找第一个 property≥n 的块。若选中 m 页块，交付前 n 页；有剩余时，将 base+n 作为 m-n 页余块的头，放回原链表位置。空闲计数只减 n，已分配块头 Property 清除。

例如按地址排列的块为 8、5、12 页，请求 4 页时 First-Fit 选 8 页块，余 4 页。它不会继续比较 5 页块是否更接近请求。

### 4.3 回收与合并

default_free_pages(base,n) 重设描述符，建立新块头并增加 n 页，然后按地址插回。先看前块末端是否等于 base，再看合并后的末端是否等于后块头。链表相邻不一定物理相邻，判断式必须是 `prev+prev->property==base` 等区间关系。

与前块合并后，base 要更新为前块头，才能继续用新头和新长度检查后块。合并只修改描述符和链表，不移动物理内存数据，也不再次增加 nr_free。

### 4.4 尾部插入缺陷

原始初始化登记和回收函数，在尾部 list_add 之后没有退出循环。循环随后访问刚插入的 base，再将其插入自己之后，使 base->page_link.prev 自指。两个分支分别增加 break 即可修复；原始测试保持不变。

本轮在临时副本撤销这两处修复，先观察原始 check_alloc_page 成功，再通过补充不变量检查捕获：

```text
check_alloc_page() succeeded!
assertion failed: list_next(le)->prev == le
```

原版缺陷复现保存在 [预期失败日志](logs/member2_first_fit_defect_portable_qemu.log)，修复后日志见 [First-Fit 回归](logs/member2_wsl_128M_first_fit_qemu.log)。复现脚本只操作临时副本，不破坏交付代码。

### 4.5 是否存在改进空间

设空闲块数为 F，First-Fit 的线性搜索最坏 O(F)，按地址定位插入点也为 O(F)。当前释放还逐页重设 n 个描述符，因此总成本为 O(n+F)。Next-Fit 可以改变搜索起点，分桶或树索引可以减少扫描，但会增加管理状态和维护成本；Next-Fit 改变了选择策略，并不保证碎片更少。

可以加强重叠检测、维护多段区间合并和并发保护。无论换何种索引，都不能保证消除所有外部碎片。原始 init_memmap 没有主动合并多次注册的相邻块，本次 Best-Fit 的登记复用了插入合并逻辑。

## 五 Best-Fit 实现与接入

### 5.1 规格

接口与框架一致，申请正整数页数，成功返回首个页描述符，失败返回 NULL。只在足够大的空闲块中选择最小块，同长优先低地址；exact fit 已是最优，可以提前结束。失败不得改变可用状态。完整规格见 [成员二规格](specs/member2.md)，可复现的输入整理见 [prompt.md](prompt.md)。

### 5.2 状态与核心函数

空闲块仍按地址排序，便于回收。best_fit_init 初始化 free_area；best_fit_init_memmap 解除合法区域的保留状态并登记块头；best_fit_alloc_pages 遍历候选、保存最小充分块，随后分割并更新计数；best_fit_free_pages 重设描述符，再由 best_fit_insert 插入并双侧合并；best_fit_nr_free_pages 返回统计。

选择规则与链表顺序并不矛盾：地址顺序解决邻接定位，全表扫描解决大小选择。对于 8、5、12 页请求 4 页，Best-Fit 选择 5 页块，留下 1 页。

best_fit_pmm_manager 注册了全部接口，其 check 指向原始 best_fit_check。pmm.c 中实际设置 `pmm_manager=&best_fit_pmm_manager`，因此运行的不是仅仅改了名称的 First-Fit。

### 5.3 不变量与边界

只有有效空闲块头留在链表，块区间按地址排序且不重叠，所有块长总和等于 nr_free。分割要保留余块头，合并要删除旧头并清标志。总页数足够仍可能因连续块不足而失败，不能只检查 n≤nr_free 就直接交付。

调用者须释放自己拥有的合法区间，当前框架不是具备完整逐页占用校验的防错分配器。!PageProperty 还可能表示空闲块内部页，不应在报告中把它解释为普遍的“已分配位”。

### 5.4 改进空间

当前申请最坏 O(F)，释放 O(n+F)。可增加按 `(块长,地址)` 排序的平衡树，用 lower_bound 寻最小充分块，另保留地址索引定位物理邻居。代价是额外空间和更复杂的拆分、回收更新。即便查块降为 O(log F)，逐页状态更新仍可能是 O(n)。

Best-Fit 最小化当前剩余量，不知道未来请求，可能积累小空闲块，因此“最佳”不是整个请求序列的全局最优。可根据实际负载比较碎片、查找成本、缓存局部性和维护开销，而不是仅凭名称判断优劣。

## 六 简化 SLUB 对象分配

### 6.1 两层架构

页层通过 alloc_pages/free_pages 获取和归还连续物理页；对象层通过 kmalloc/kfree 在已取得的页内分配小槽位。SLUB 不访问 Best-Fit 私有 free_area，因此页策略可替换，但替换后必须符合实际页数和释放长度契约。

接口 slub_init 仅在 pmm_init 成功后执行一次。kmalloc(0) 返回 NULL，kfree(NULL) 无操作，OOM 返回 NULL，返回对象按 16 字节对齐且不保证清零。

### 6.2 小对象缓存

缓存规格为 16、32、64、128、256、512、1024、2048 B。每个 slab 从底层取得一页，在页头保存魔数、缓存编号、容量、inuse、页数、freelist、链表节点和 32 B 位图；头部按 16 B 对齐，容量由真实 header_size 计算，不能简单用 4096/规格。

空闲对象前部保存下一空槽地址。分配时弹出 freelist、设置位图、增加 inuse；交给调用者后，原先存链接的字节可以正常写业务数据。释放后对象重新交给分配器，调用者不得继续访问。

### 6.3 partial、full 与 empty

只把未满 slab 放进 partial 链表。申请优先复用已有页，必要时才向底层取页；满页移出链表。回收时若由 full 变为 partial，重新接入；inuse 变 0 时删除页记录并归还整页。

释放一个对象不一定使 nr_free_pages 增加。若同页仍有其他活对象，只增加对象层空槽数；最后一个对象释放并归还页后，页层计数才增加。这体现了两层管理的资源粒度差异。

### 6.4 大对象与异常

超过 2048 B 的请求分配 `ceil((size+header_size)/4096)` 个连续页，在头部记录页数。kfree 用原始返回指针找到头部并按记录归还。4096 B 请求通常占两页，因为头部也占空间。

计算 size、头部和舍入余量之和前检查溢出；页分配失败不写入 NULL。小对象回收检查魔数、缓存编号、槽位边界与位图。此类检查不能保证任意野指针安全，也不能允许重复释放、内部地址释放或释放后使用。

### 6.5 简化范围与改进

当前为单 hart 教学实现，没有锁、每 CPU 缓存、NUMA、对象构造器或压力回收。立即归还空页便于检查泄漏，但频繁申请回收时可能增大底层调用成本；保留少量空页可减少这种成本，也会增加驻留内存。

更多规格可减少部分内部余量，却增加缓存管理复杂度。并发版本必须共同保护链表、freelist、位图、计数及底层页状态，不能只给 inuse 加原子操作就宣称线程安全。

member2_page_check 先构造多个不同长度、相同长度的空闲块，检查最小充分块与同长低地址选择；再检查分割余块、乱序释放形成双侧合并，以及耗尽后 NULL 返回。隔离整个空闲区后释放两个不相邻的 2 页块，验证总共 4 页仍无法满足 3 页连续请求。

SLUB 自检让 300 个对象同时存活，其中前 260 个为 16 B，以跨越最小对象 slab 容量；其余覆盖所有规格边界与 2048/2049、4096 等大对象边界。所有活区间两两不重叠，写入并逐字节检查内容；从满页释放后要求下次复用该槽位；以 137 为步长对 300 项置换回收，最终页数恢复。还通过持有所有空闲页检查底层 OOM，以及 0、NULL 和最大长度边界。

这些是实现者配套检查，不代替成员三独立测试。没有据此声称所有非法调用、长时间随机负载、多核并发或所有平台均已验证。

## 八 成员一页表与 TLB 调试结果汇总

成员一原始 os2026 日志记录了 guest 内核 GDB 与 host QEMU GDB 的配合。取指地址 0xffffffffc02000d8 的根表物理地址为 0x80205000，索引 511，读取 PTE 地址为 0x80205ff8，PTE 值为 0x200000cf。根项是 1 GiB 叶子，循环第一轮完成，不继续读取下一级表。

## 九 Buddy System 与独立 SLUB 测试

### 9.1 为什么单独实现 Buddy

First-Fit 与 Best-Fit 用一条按地址排序的空闲块链，分配时切出恰好 n 页。
Buddy 则把内存组织成 2^k 页的块，用块首地址的异或定位伙伴：

```text
buddy_pfn = pfn XOR (1 << order)
```

申请时从满足 `2^k >= n` 的最小阶往上找，找到后逐级二分；释放时只与
同阶、仍空闲、且是块首的伙伴合并。代价是内部碎片（最多不到请求的两倍），
收益是拆分与合并都在 O(log N) 内完成，且合并规则与分配历史无关。

### 9.2 阶数必须记在块首

这是本模块最关键的接口决定。SLUB 的大对象路径保存的是请求页数：

```c
size_t npages = (size + header_size() + PGSIZE - 1) / PGSIZE;
struct Page *p = alloc_pages(npages);
...
free_pages(pa2page(PADDR(s)), npages);
```

若请求 3 页，Buddy 只能给 4 页块（order 2）。如果 `free_pages(base, 3)`
只归还 3 页，第 4 页就永久泄漏；更糟的是把它拆成 3 页块会破坏伙伴关系。
本实现在分配时把真实阶数写进块首 `property`，释放时读回：

```text
alloc_pages(3)       -> order 2, block = 4 pages, base->property = 2
free_pages(base, 3)  -> 读回 order 2，完整归还 4 页
```

同时断言 `2^order >= n > 2^(order-1)`，请求与块大小不符时直接失败，
而不是悄悄接受。这样 SLUB 源码一行不改就能在 Buddy 下正确工作。

### 9.3 初始化分段

`page_init` 交出的空闲区起点是任意的（本机为 `0x8038c000`），不一定按大阶
对齐。`buddy_init_memmap` 因此把区间拆成若干「按自身大小对齐」的 2 的幂块：

```text
while remaining > 0:
    order = 能同时满足 2^order <= remaining 且 pfn 按 2^order 对齐的最大阶
    登记该块；cur += 2^order; remaining -= 2^order
```

不能直接按最大阶切分后就假设对齐，否则伙伴下标计算会落到别的块上。

### 9.4 测试覆盖

Buddy 的独立测试（`kern/mm/member3_buddy_test.c`）：

| 编号 | 场景 | 能发现的缺陷 |
|---|---|---|
| T1 | 1..10 页的阶数取整 | 把请求页数当作阶数 |
| T2 | 逐页耗尽后逆序归还 | 丢页、错误合并、计数漂移 |
| T3 | 超量与 SIZE_MAX 请求 | 失败路径改动链表 |
| T4 | 最大块拆分后释放 | 拆分余块丢失、形状未恢复 |
| T5 | 奇数页与后一页同时释放 | 只按物理相邻合并 |
| T6 | 各阶块起址对齐 | 未对齐导致伙伴定位错误 |

独立 SLUB 测试（`kern/mm/member3_slub_test.c`）覆盖规格边界两侧、同页共享、
跨页与多页对象、full→partial 复用、240 个混合活对象的区间不重叠、数据保持、
部分释放后存活对象、乱序回收、0/NULL/溢出长度，以及真实页耗尽。

其中 OOM 用例逐页调用 `alloc_page()` 直到 NULL，而不是

## 十 思考题与原理对应

### 10.1 OS 如何得到物理内存范围

应优先从固件或启动协议获得结构化布局，再校验并扣除保留区。本实验使用传入 DTB 的 memory/reg；其他平台可通过 UEFI GetMemoryMap、传统 x86 E820 或受支持的平台接口取得布局。不能把 malloc 当作发现 RAM 的方法，也不能通过盲写未知地址可靠识别全部可用内存，因为物理地址中可能存在 MMIO、空洞和占用空间。

“地址存在”“属于 RAM”“当前允许分配”是不同条件。成员一完整论述及其引用资料见原报告的 Challenge 一节。

### 10.2 重要知识点、关系与差异

| 实验内容 | OS 原理概念 | 联系与差异 |
|---|---|---|
| DTB 与保留区 | 资源发现、物理地址空间 | 取得 RAM 范围仍需判断哪些部分可分配 |
| Page 描述符 | 物理页帧管理 | 管理记录不是被管理页，记录本身也占内存 |
| 固定偏移 PADDR | 内核直接映射 | 只适用于该映射，不能用于任意进程地址 |
| 根级 Sv39 叶子 | 多级页表、大页 | 最多支持三层不等于每次都读三层 |
| First/Best-Fit | 连续物理分配 | 选择规则不同，均可能存在外部碎片 |
| 双侧合并 | 空闲区合并 | 修改元数据，不搬移数据，也不重复增加页数 |
| Buddy | 按阶分配 | 易拆分合并，向上取整可能产生内部碎片 |
| 简化 SLUB | 对象缓存 | 在页层之上减少小对象独占整页的浪费 |
| TLB 与 sfence.vma | 地址翻译缓存与同步 | TLB 不是数据缓存，QEMU soft TLB 还服务于模拟执行 |
| 测试不变量 | 实现正确性 | 测试通过只证明所覆盖场景，不等于所有负载均正确 |

### 10.3 重要但未完整实现的理论内容

本阶段没有实现完整的每进程用户地址空间、按需分页与缺页处理、页面置换、交换区、写时复制、完整共享内存生命周期、多核 TLB 一致性、并发分配和 NUMA。当前内核初始化成功不能推出这些机制已经具备。
