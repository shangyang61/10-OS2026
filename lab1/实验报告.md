## 一、实验目的

1. 理解 QEMU 模拟的 RISC-V 机器如何从复位进入内核。
2. 理解链接脚本、入口汇编和内核栈在启动时的作用。
3. 用 QEMU 和 GDB 检查启动地址、指令和栈指针，并观察内核输出。

## 三、实验整体逻辑分析

### 3.1 启动流程

Makefile 将 C 代码和汇编代码编译为 RISC-V 目标文件，再按 `tools/kernel.ld` 链接为 `bin/kernel`。链接脚本把入口 `kern_entry` 放在 `0x80200000`。`objcopy` 将 ELF 文件转换为原始镜像 `bin/ucore.img`。

运行时，QEMU 将镜像加载到 `0x80200000`。CPU 从复位地址 `0x1000` 执行，随后进入 OpenSBI。OpenSBI 初始化后跳转到内核入口。`entry.S` 设置内核栈并跳到 `kern_init`；`kern_init` 清零 BSS、打印启动信息，然后进入无限循环。

### 3.2 输出过程

`kern_init` 调用 `cprintf`；格式化后的字符依次经过 `cons_putc`、`sbi_console_putchar` 和 `sbi_call`。`sbi_call` 执行 `ecall`，由 OpenSBI 完成控制台输出。

## 四、实验内容与实现

### 练习 1：理解内核启动中的程序入口操作

**负责人：秦东杰（2411738）。**

`entry.S` 中的 `.space KSTACKSIZE` 预留内核栈空间。`la sp, bootstacktop` 将栈顶地址写入栈指针 `sp`，使后续 C 函数可以使用内核自己的栈。本次 GDB 观察到：进入 `kern_entry` 时 `sp=0x8001bd80`；执行栈设置指令后，`sp=0x80203000`。

`tail kern_init` 直接跳转到 `kern_init`，不保存返回到 `kern_entry` 的地址。`kern_init` 打印信息后进入无限循环，因此不需要返回。反汇编显示，跳转指令位于 `0x80200008`，目标 `kern_init` 位于 `0x8020000a`。

### 练习 2：使用 GDB 验证启动流程

**负责人：邹俊轩（2412592）。**

在一个终端运行 `make debug`，让 QEMU 启动后暂停并开放 GDB 端口；在另一个终端运行 `make gdb`，加载 `bin/kernel` 的符号并连接 QEMU。先查看复位处的 PC 和指令，再在 `0x80200000` 设置断点，继续运行到内核入口。

```text
连接后：pc = 0x1000，sp = 0x0
0x1000: auipc t0,0x0
0x1004: addi  a1,t0,32
0x1008: csrr  a0,mhartid
0x100c: ld    t0,24(t0)
0x1010: jr    t0

内核入口：pc = 0x80200000，sp = 0x8001bd80
设置内核栈后：sp = 0x80203000
```

上电后最先执行的指令位于 `0x1000`。这段复位代码准备启动参数、读取硬件线程编号 `mhartid`，再跳转到固件。OpenSBI 完成初始化后进入 `0x80200000` 处的 `kern_entry`；GDB 在该地址命中断点。

## 六、实验总结与收获

本实验把编译、装载和启动三个步骤连了起来。`kernel.ld` 确定内核入口地址；`entry.S` 建立内核栈；`kern_init` 完成 BSS 清零和输出。通过 GDB，我们确认 CPU 先从 `0x1000` 执行，再进入 `0x80200000` 处的内核；栈指针也按入口汇编的要求改变。

| 实验知识点 | 对应的操作系统知识 |
|---|---|
| 交叉编译 | 在 x86_64 环境中生成 RISC-V 目标代码 |
| 链接与装载 | 链接地址和实际加载地址需要对应 |
| 内核入口与栈 | 内核进入 C 函数前需要设置可用的栈 |
| SBI 输出 | 内核通过 `ecall` 请求固件提供控制台服务 |
| GDB 调试 | 用寄存器和反汇编核对实际执行流程 |
