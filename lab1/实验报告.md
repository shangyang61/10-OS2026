## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

Lab1 要回答“最小内核如何开始执行”。交叉编译器把源文件编译为 RISC-V 目标文件；链接脚本把内核入口定位在 `0x80200000`；Makefile 生成 `bin/kernel` 和 `bin/ucore.img`。QEMU 的复位代码先运行，随后 OpenSBI 初始化机器并将控制权交给内核。内核入口建立自己的栈，跳入 C 函数 `kern_init`，通过 SBI 控制台打印信息，然后进入无限循环。

### 2.2 功能的逐步实现

1. **编译与链接：**Makefile 调用 `riscv64-unknown-elf-*` 工具；`tools/kernel.ld` 指定 `kern_entry` 和各段布局。入口地址必须与固件交接地址一致。
2. **镜像加载与固件启动：**原始 Makefile 使用 `-device loader,file=bin/ucore.img,addr=0x80200000`；QEMU 4.1.1 启动随附的 OpenSBI v0.4。
3. **内核入口：**`kern/init/entry.S` 把 `sp` 设为 `bootstacktop`，再尾跳转到 `kern_init`。
4. **输出与停机状态：**`kern_init` 清零 BSS，调用 `cprintf` 打印提示，最后进入无限循环；字符经控制台驱动和 SBI `ecall` 输出。
5. **实测验证：**GDB 观察复位 PC、最初的机器指令、内核入口断点以及栈指针变化。

## 四、实验内容与实现

### 练习 1：理解内核启动中的程序入口操作

**负责人：**待填写。

`la sp, bootstacktop` 将 `bootstacktop` 的地址装入栈指针寄存器 `sp`。内核不能依赖前一阶段固件留下的栈，因此必须先建立自己的栈，之后才能可靠地运行 C 代码。GDB 在 `kern_entry` 处看到执行前的 `sp=0x8001bd80`；执行该伪指令展开的指令后，`sp=0x80203000`，与 `bootstacktop` 的地址相同。

`tail kern_init` 直接跳转到 `kern_init`，不建立返回 `kern_entry` 的调用路径。`kern_init` 声明为 `noreturn`，打印后进入无限循环，所以无须返回。反汇编中尾跳转位于 `0x80200008`，目标 `kern_init` 位于 `0x8020000a`。

### 练习 2：使用 GDB 验证启动流程

**负责人：**待填写。

使用原始 Makefile 的镜像加载参数启动 QEMU 4.1.1，并用 `-S` 暂停虚拟 CPU、在本地端口开放 GDB 连接。SiFive `riscv64-unknown-elf-gdb` 加载 `bin/kernel` 的符号并连接 QEMU；在复位处查看 PC 和指令、单步执行，再对 `0x80200000` 设置断点并继续。实测记录：

```text
连接后：pc = 0x1000，sp = 0x0
0x1000: auipc t0,0x0
0x1004: addi  a1,t0,32
0x1008: csrr  a0,mhartid
0x100c: ld    t0,24(t0)
0x1010: jr    t0

Breakpoint 1, kern_entry at 0x80200000
入口前：sp = 0x8001bd80
栈初始化后：sp = 0x80203000
0x80200008: j 0x8020000a <kern_init>
```

**问题回答：**硬件复位后首先执行的指令位于 `0x1000`，属于 QEMU 提供的复位 ROM。它准备启动参数，读取硬件线程编号 `mhartid`，取得固件入口并跳转。OpenSBI 随后完成机器态初始化，再把控制权交给位于 `0x80200000` 的内核。入口断点命中 `kern_entry`，证实 CPU 已开始执行内核第一条指令。

## 六、实验总结与收获

### 对操作系统的理解

| 实验知识点 | 对应 OS 原理及关系 |
|---|---|
| 交叉编译 | x86_64 宿主机生成 RISC-V 64 位目标代码，产物须符合目标指令集与 ABI。 |
| 链接脚本与入口 | 内核链接地址、镜像加载地址和固件跳转地址必须相互对应。 |
| 固件与特权级 | 复位 ROM、OpenSBI、S 态内核构成启动链；内核通过 SBI 请求固件服务。 |
| 内核栈 | 进入 C 函数之前建立独立栈，支持函数调用与局部数据。 |
| 早期控制台 | `cprintf` 经控制台驱动与 SBI 输出字符，提供早期调试手段。 |
| 远程调试 | QEMU 模拟目标机器，GDB 查看指令与寄存器，以运行证据验证启动流程。 |

页表、虚拟内存、异常和中断处理、进程调度、系统调用、文件系统与同步互斥也属于重要的 OS 原理，但不在 Lab1 最小内核的实现范围内。

### AI 协作开发的经验

本实验没有编写内核代码，也没有提示词驱动的函数实现。对启动流程的分析以原始源码和实际 GDB 输出为依据；报告中的地址、版本与运行结果均来自最终实验环境。
